## v0.0.4

Release date: 2026-10-14

### New Features

- Added `flvt env init`, `env set`, `env list`, and `env validate` for defining,
  storing, masking, and checking encrypted environment profiles.
- Added safe `.env` migration through `flvt env import`; source files remain
  unchanged and profile replacement requires explicit confirmation.
- Added explicit Local and Shared vault modes.
- `flvt init` creates a Local vault by default; `flvt init --shared` opts into
  a Shared vault for new workspaces.
- Local initialization uses the repository-local `.git/info/exclude` for
  `.vault/`, while Shared initialization leaves the vault trackable by Git.
- Added explicit external vault paths while keeping note sources and anchors
  relative to the workspace root.
- Added a VS Code Tag Explorer with tag search, multi-tag queries, suggestions,
  colors, statistics, and management actions.
- Added workspace note search with text, tag, file, and symbol filters.
- Added an expandable CodeLens note viewer and a unified Add / Edit Note action
  with a remappable shortcut and explicit Line/Symbol choice.
- Added a VS Code Environment view for managing environment profiles.

### Improvements

- The selected mode is stored as the top-level `mode` field in
  `.vault/workspace.json` and is shown by `flvt init` and `flvt status`.
- Initialization does not modify `.gitignore`.
- Vault initialization no longer generates `.vault/AGENTS.md`; existing
  user-owned files are preserved.
- Vault safety is enforced by Core and CLI behavior rather than generated AI
  instruction files.
- New Local Vaults in Git checkouts are stored under Git metadata, while Shared
  Vaults use the project-root `.vault/`.
- Vault selection, note refreshes, and editor draft recovery are more reliable.

### Bug Fixes

- Prevented read and status commands from implicitly initializing a Vault.
- Improved protection against stale note results and repeated refreshes in the
  VS Code Notes and Tags views.
- Preserved tag and Vault data integrity across concurrent and external-path
  operations.

### Install

- Install or update `FrilVault` from the Visual Studio Marketplace.
- For manual installation, download the VSIX for your platform from the GitHub
  Release and use `Extensions: Install from VSIX...` in VS Code.
- Marketplace users do not need to choose a platform manually.

### Upgrade Notes

- Existing workspace metadata without a `mode` field remains valid and is
  interpreted as Local. Existing notes and metadata are preserved when a
  workspace is initialized again. There is no mode-switch or migration command
  in this release.
- No note data migration is required. Existing Vaults keep their current path
  and stored mode.
- The VS Code extension bundles `flvt` in each platform package.

### Known Limitations

- The VS Code extension targets one workspace root at a time in multi-root
  workspaces.

## v0.0.3

Release date: 2026-07-27

### New Features

- Added note count badges beside files and aggregated folders in the built-in VS Code Explorer.
- Added a workspace note overview to `FrilVault Notes` when no editor file is active.
- Added folder and file note counts with direct navigation to source files.

### Improvements

- Adding a note from a blank cursor line now prefers a line anchor.
- Command labels are more compact, while the Explorer view remains clearly named `FrilVault Notes`.
- Editor CodeLens actions are labeled `Note Add` and `Note Edit`.

### Bug Fixes

- Fixed the workspace overview repeatedly returning to `Loading workspace notes...` after a successful load.
- Registered the missing `frilvault.notesPanel.openNote` command contribution.
- Workspace overview data now comes directly from the vault explorer output.

### Install

- Install or update `FrilVault` from the Visual Studio Marketplace.
- For manual installation, download the VSIX matching your platform from the GitHub Release.

### Upgrade Notes

No vault data migration is required. FrilVault continues to use the bundled `flvt` CLI.

## v0.0.2

### New Features

- Added platform-specific VSIX packages for:
  - `darwin-arm64`
  - `darwin-x64`
  - `linux-x64`
  - `win32-x64`

### Improvements

- Bundled the FrilVault CLI with the VS Code extension.
- Removed the requirement to install `flvt` separately for supported VS Code installs.
- Improved release delivery by attaching platform-specific VSIX packages to each GitHub Release.

### Bug Fixes

- Fixed note creation failing on fresh Marketplace installations when no external `flvt` binary was installed.
- Improved diagnostics when the bundled CLI cannot start or does not match the expected version.

### Other Changes

- `frilvault.cliPath` is now an optional advanced override.
- The extension uses its bundled CLI by default.
- Marketplace publishing and GitHub Release asset generation now run as separate workflows.

### Install

- Install from the Visual Studio Marketplace for the default experience.
- Install from GitHub Release by downloading the matching VSIX and using `Extensions: Install from VSIX...` in VS Code.
- Marketplace users do not need to choose a platform manually. The Marketplace selects the matching package automatically.

### Upgrade Notes

No vault data migration is required.

## v0.0.1

### Initial Public Preview

- Published the first FrilVault VS Code extension.
- Added line and symbol anchored notes.
- Added local `.vault` persistence.
- Added note creation, editing, deletion, search, statistics, health, and repair features.

### Known Issue

The extension required a separately installed `flvt` CLI.

Without the CLI, note persistence failed with a generic `Save failed`
message. This limitation was fixed in v0.0.2.
